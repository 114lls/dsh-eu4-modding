# 深度剖析：为什么 EU4 的失败是静默的

> 本文回答一个问题：**为什么 EU4 模组写错了不报错、不闪退，只是不生效？**
> 每个论断都附实测证据（`文件:行` 或 error.log 原文）。

## 一、静默失败的三种机制

### 机制 1：解析器容错 —— 认不出的 key 被丢弃，不中断

Clausewitz 的脚本解析器是**容错式**的：遇到不认识的 key，它记一条 error.log，
然后**继续解析后面的内容**。

后果：一个错 key 只影响它自己所在的那个块，其余内容照常加载。
所以「模组大部分功能正常、某一条不生效」是最常见的症状 —— 用户很容易以为
「是游戏机制没触发」，而不是「我写错了」。

### 机制 2：效果语义丢失 —— 名字对了类型，但类型错了位

最典型的是把触发器写在效果位：

```
immediate = { treasury = -50 }
```

`treasury` 是**触发器**（判国库是否 ≥ X）。写在效果位，游戏报：

```
[persistent.cpp:88]: Parsing Error. File: "events/zz_epi_chain_1.txt",
                     Error: Unknown effect type. Key: treasury
```

这条报错在 error.log 里，**但游戏界面没有任何提示**。事件链整条失效，
玩家只看到「点了决议没反应」。

正确写法：

```
immediate = { add_treasury = -50 }          # 定额
immediate = { add_years_of_income = -0.5 }  # 按岁入比例（推荐，平衡性好）
```

### 机制 3：事件被静默丢弃 —— 非法 ID 不报界面，只写日志

```
namespace = zz_epi_chain1      # 含数字
```

游戏报：

```
[eventmanager.cpp:434]: Incorrect namespace event id: zz_epi_chain1.
```

然后**把这个 namespace 下的所有事件丢弃**。不闪退、不弹窗。
玩家看到的是「事件永远不触发」。

实测依据：vanilla `events/*.txt` 共 365 处 namespace 声明、364 个唯一值，
**无一含数字**（全目录扫描，0 例外）。所以「namespace 只用字母」不是风格建议，
是引擎约束。

## 二、四个实证案例（都来自真实踩坑）

| # | 写法 | error.log 原文 | 症状 | 为什么静默 |
|---|---|---|---|---|
| 1 | 效果位写 `treasury = -50` | `Unknown effect type. Key: treasury` | 事件链全失效 | 解析器继续跑，只是丢了这个效果 |
| 2 | `namespace = zz_epi_chain1` | `Incorrect namespace event id: zz_epi_chain1.` | 事件永不触发 | 事件被丢弃，无界面提示 |
| 3 | 选项内套 `effect = { }` | `Unknown effect type. Key: effect` | 点了没反应 | 同 1，只丢这个块 |
| 4 | 权重块里的名字被漏统计 | （无报错 —— 这是工具侧问题） | lint 对合法名字报假错 | 见下节 |

### 案例 4 特别说明：这是**工具**的静默失败，不是游戏的

在构建白名单时，我最初只把「含 `factor` 的 `modifier` 块」识别为触发器语境。
结果 39 个只在 AI 权重块里出现的**真触发器**（`prestige` / `legitimacy` /
`war_exhaustion` / `land_morale` …）被整体漏收进白名单。

后果不是游戏报错，而是**lint 会对这些合法名字报「查不到」** ——
一次工具侧的假错。修复后 `triggers` 从 985 涨到 1024 个名字。

这条印证了同一个母题：**静默的失败不只发生在游戏里，也发生在工具里**。
工具错了不报错，只是给出错误结论。

## 三、为什么「先备份 + 每步校验」是唯一可靠的流程

既然失败是静默的，人眼审查就不可靠。可行的办法只有两个：

1. **静态校验**：在进游戏之前把能查的都查掉
2. **日志分诊**：进游戏之后，从 error.log 里找出属于自己的那几行

第 2 条的前提是**能分辨噪声**。实测本机三份日志：

```
物理行 93,433 | 非空行 53,537 | 日志条目 50,513
可归属到自己 mod 的：1 行
噪声占比：95.8%
```

95.8% 的日志是别人的错（原版 + 几十个工坊 mod 并存）。
所以流程必须是：

```
只启用原版 + 你的 Mod   →   grep 自己的文件名/ID   →   一次只改一类   →   重跑
```

## 四、静默失败的代价：为什么值得为它写 12 个工具

如果失败会崩溃，用户立刻知道要修。
静默失败意味着**错误会一直活到发布**，然后在玩家那里表现为
「这个 mod 的某个功能好像不太对」，而作者无法复现。

这就是本项目把重心放在静态校验和日志分诊、而不是文档篇幅的原因
（见 SKILL.md §1.0）：

- 名字位判定必须**按容器类型**（不靠名字形态）
- 分级必须 `error` 只在「能证明会不生效」时使用
- 基准必须可复现（否则「验证通过」本身也是静默的假象）
